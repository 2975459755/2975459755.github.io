## 存储

### 存储器概念

#### ：存储器分类

- 按作用/计算机层次

辅存/外存 -> 主存/内存 -> Cache

符合金字塔型，容量依次减小，速度依次加快，成本依次增加

- 按存储介质

磁表面存储器（磁盘、磁带），磁芯存储器，半导体存储器（CMOS型，双极型），光存储器（光盘）

- 按存取方式

1. 随机存储器（RAM）：可以随机存取，速度与位置无关，主要用于主存和cache，分为静态和动态RAM
2. 只读存储器（ROM）：信息一旦写入就不能改变，断电不丢失。衍生类型包含可反复重写的存储器，如电擦除，但仍保留了断电不丢失、随机读取的特性，且写入很慢
3. 串行访问存储器：包括顺序存取（磁带）和直接存取（磁盘，光盘），存取时需要按物理位置先后顺序进行寻址，速度与位置有关

> 直接存取介于顺序存取和随机存取之间，在大区域中随机，在小区域内（磁道）顺序

- 按信息可保存性

易失性存储器：如RAM，断电丢失数据

非易失性存储器：如ROM，断电不丢失数据

破坏性读出／非破坏性读出：按数据读出时，原存储信息是否被破坏区分

#### ：存储器性能计算

- 存取时间

- 存取周期：两次独立访存之间所需的最小时间间隔，包含存取时间和复原时间

- 主存带宽

#### ：多级存储

主要思想是上一层的存储器作为低一层的高速缓存，解决速度、容量、成本三者间的矛盾

主存和外存间的数据调动由硬件和操作系统共同完成，对应用程序员透明

### DRAM

电路细节：湖科大4-3-1

与SRAM相反，DRAM集成度高，功耗小，但无法稳定保持数据，且读操作会破坏数据，需要频繁刷新

- DRAM与SRAM的对比

|  | DRAM | SRAM |
| 组成元件 | 1个MOSFET和1个电容（少） | 6个MOSFET（多） |
| 集成度 | 高 | 低 |
| 存储成本 | 低 | 高 |
| 发热量 | 小 | 大 |
| 速度 | 略慢 | 快 |
| 应用 | 主存 | cache |
| ***读后回写*** | 需要（破坏性读取） | 不需要（非破坏性读取） |
| ***动态刷新*** | 需要（电容电荷泄露） | 不需要（额外保持元件） |
| ***行列地址输入*** | 分两次（地址线复用） | 一次完成 |
| 可保存性 | 易失性 | 易失性 |

#### ：刷新策略

DRAM刷新时不能响应外部访问，因此CPU访问DRAM与内存控制器刷新DRAM的操作存在内存争用问题，为此有三种刷新策略

![DRAM刷新方式](DRAM刷新方式.png)
_图中时隙可以理解为一个存取周期，总长为一个刷新周期_

- 集中刷新：在一个*刷新周期*（图中2ms）内，利用一段固定时间（若干*存取周期*)，依次刷新所有行，这段时间存储器无法读写，称为死区

- 分散刷新：相当于将原*存取周期*加上刷新1行的时长作为新的存取周期，因此没有了死区。但是这种方法刷新过于频繁，严重影响速度，因此不适用于高速存储器

- 异步刷新：让一个刷新周期内，每一行刚好刷新一次

### 主存储器的优化（多模块存储器）

通过存储器的并行工作来提高速度

#### ：单体多字

按同一地址同时访问不同内存条的同一单元，单体多字的构建本质与位扩展完全一致，只是更宏观

![单体多字](单体多字.png)
_常见的多通道技术就是单体多字_

缺点：只有指令和数据在主存中连续存放时，才能有效提升速度，一旦操作数不连续存放，或遇到转移指令，提升就不明显

#### ：多体交叉（多体并行）

分为高位多体交叉和低位多体交叉两种编址方式

- 高位多体交叉（顺序编址）

![高位多体交叉](高位多体交叉.png){: .w-50}
_地址又称 体号+体内地址_

高位多体的地址是连续的，本质上仍是顺序存储，同一个数据分布在同一个存储器内，没有实现并行工作，无法提高效率

- 低位多体交叉（交叉编址）

![低位多体交叉](低位多体交叉.png){: .w-50}
_地址又称 体内地址+体号_

为提高顺序访问时存储模块的并行性，各存储模块均有独立的地址寄存器、数据寄存器和读写控制电路

> 顺序访问时，按**流水线**方式访问\
设存储模块的存取周期为 $T$，其他延迟（如总线传输周期）为 $\tau$，模块数 $m$\
![低位多体交叉的流水线访问](低位多体交叉的流水线访问.png){: .w-50}
- 要实现流水线访问，需满足条件 $T = m * \tau$
- $n$ 次流水线耗时 $nT + (m - 1)\tau$
- 可从任意地址（任意存储模块的任意单元）开始顺序访问
{: .prompt-info}

若相邻 $n$ 次访问的地址出现在同一个模块内，则会发生访存冲突，需要延迟访存请求

### Cache：概念

![cache分类](cache分类.png)
_存在性能差异的地方都可以用到cache技术_

#### ：程序局部性

- 时间局部性：某个被访问的存储位置在一段时间内可能被多次访问
> 例：循环结构，子程序调用

- 空间局部性：某个被访问的存储位置，其附近的存储位置可能也会被访问
> 例：数组，向量，结构体，顺序执行的代码块

> 举例分析：以下C程序的局部性\
`for (i = 0; i < 100; i ++) sum += a[i];`
1. for循环的*指令序列*（读取、加法）在主存中顺序存放：*空间局部性*；
2. for循环中的指令序列被执行100次：*时间局部性*；
3. i、sum变量：有*时间局部性*，没有空间局部性；
4. 数组a的数据在主存中顺序存放：有*空间局部性*，没有时间局部性（每个只访问一次）

#### ：Cache性能计算

- 命中访问时间 $t_c$ = cache内查找时间 + cache访问时间

- 缺失补偿（时间）= cache内查找时间 + *主存访问时间* $t_m$ + cache访问时间

- 命中率、缺失率

命中率 $h = \frac{n_c}{n_c + n_m}$

其中 $n_c$ 为命中次数，$n_m$ 为缺失（调用主存）次数

缺失率 = $1 - h$

- 访问效率 $e = \frac{1}{h + (1 - h)r}$

$e = \frac{t_c}{t_a} = \frac{t_c}{ht_c + (1 - h)t_m} = \frac{1}{h + (1- h)\frac{t_m}{t_c}}$ 其中 $\frac{t_m}{t_c} = r$

#### ：cache基本工作原理

cache被划分成等长的数据块，又称数据行，每行包含若干数据字

缺失时，缺失数据相邻的数据也会被载入cahe，以利用空间局部性

数据块的地址由块地址和块内偏移地址（offset）组成

## 总线

### 总线概念

#### ：总线分类

- 片内总线：芯片内部的总线

- 系统总线：连接CPU、主存、IO的总线，又可分为三类：
1. 数据总线：数据，指令，中断信号
2. 地址总线：单向的
3. 控制总线：命令、反馈和定时信号

- IO总线：目的是将低速和高速总线分离

- 通信总线：即外部总线

按时序控制：

- 同步总线：按统一时钟节拍同步

- 异步总线：以信号握手的方式来协调

按数据传输方式：

- 串行总线

- 并行总线：线路之间可能会干扰，因此实际速度不一定更快；更适合短距离通信

#### ：系统总线的结构

- 单总线结构

- 双总线结构：主存总线 + IO总线，分离了高/低速的传输

- 三总线结构：主存总线 + IO总线 + DMA总线，提高了IO设备的性能，但同一时刻只能使用一种总线

\[图片]

#### ：总线的性能计算

- 总线时钟周期
- 总线时钟频率
- 总线传输周期：一次总线操作所需的时间
- 总线工作频率
- 总线宽度（位宽）
- **总线带宽 = 总线宽度 * 总线工作频率**
- 总线复用：地址/数据线复用
- 信号线数：地址/数据/控制三种线数的总和

### 总线事务

过程：请求阶段 -> 仲裁阶段 -> 寻址阶段 -> 传输阶段 -> 释放阶段

- 非突发传送：主从设备之间每次传送一个字长的数据，每个传送周期内都需要先传送地址

- 突发传送：成组数据传输完成后再释放总线

### 总线定时

#### ：同步定时

统一时钟信号控制，总线周期恒定

优点：传输速度快，控制逻辑简单

缺点：无法进行校验，可靠性差

适用于总线长度较短（不易出错），各部件存取时间接近的系统

#### ：异步定时

通过握手信号（请求、回答信号）实现控制

优点：适应速度差距大的部件

缺点：实现复杂，速度稍慢

根据请求和回答信号是否互锁，分为3种类型：

\[图片]

- 不互锁方式

主设备发出请求信号后，不等待回答信号，而是过一段时间自行撤销请求；从设备接到请求信号后，发出回答信号，并过一段时间自行撤销

- 半互锁方式

主设备发出请求信号后，必须接到回答信号，才撤销请求；从设备会自行撤销回答信号

- 全互锁方式

主设备发出请求信号后，必须接到回答信号，才撤销请求；从设备发出回答信号后，必须获知主设备已撤销请求，才撤销回答信号

异步串行通信方式（wd P292）

#### ：半同步定时

增加一条`Wait信号线`，例如，数据未准备好时，保持wait信号无效，直到数据准备好后，主设备再取数据

#### ：分离式定时

前三种定时方式，在从设备准备数据时，总线处于空闲状态，而分离定时方式就是为了优化这一点；主设备发送请求信号后，立即释放总线；从设备接到请求，在准备好数据后再申请总线使用权

## I/O

### IO接口

#### ：功能

1. **地址译码和设备选择**
2. 主机和外设的通信控制
3. **数据缓冲**：由数据缓冲寄存器实现，避免因速度不一致（或应答不及时？）而丢失数据
4. 信号格式转换
5. 传送控制命令和状态信息

#### ：结构

\[图片]

- 数据缓冲寄存器：暂存数据信息

- 状态寄存器：记录接口和设备的状态信息

- 控制寄存器：保存cpu对外设的控制信息

- 数据线：传输读写数据、状态信息、控制信息和中断类型

- 地址线：传输要访问的IO接口的寄存器的地址

- 控制线：传输读写控制信号、中断请求、响应信号、仲裁信号、握手信号

状态、控制寄存器传送方向相反，访问时间不重合，因此可以合二为一

IO接口的类型（WD P302)

#### ：端口编址

`端口`是指接口电路中可以进行读写的寄存器

- 统一编址（存储器映射）

把主存地址空间分出一块给IO端口编址，因此无需设置专用IO指令，可以用访存指令

由于在识别IO端口时全部地址线都参加译码，因此译码电路更复杂，译码速度降低

- 独立编址（IO映射）

IO地址空间与主存地址空间互相独立，由专门的`IO指令`来区分访存/访问IO端口，因此程序设计的灵活性较差，并增大了控制的复杂性

### 程序查询方式

\[图片]

程序查询方式中设置一个数据缓冲寄存器（数据端口）和一个设备状态寄存器（状态端口）

- 独占查询：外设和CPU串行工作，一旦设备启动，CPU就会一直查询接口状态

- 定时查询：CPU周期的查询接口状态，条件满足时传输一个数据，然后返回用户程序

### 程序中断方式

#### ：程序中断流程

> CPU响应中断的条件：\
开中断（异常和不可屏蔽中断除外）\
一条指令执行完毕（异常除外）
{: .prompt-info}

- 中断请求

为记录并区分不同中断源，对每个中断源设置`中断请求标记触发器`，一系列触发器组成中断请求标记寄存器，该寄存器可以集成于CPU中，也可以分散在中断源中

可屏蔽中断通过`INTR线`发出，不可屏蔽中断通过`NMI线`发出

- 中断响应判优

中断响应优先级时CPU响应中断请求的先后顺序，通过`硬件排队器`（或中断查询程序）实现

> 中断优先级：\
不可屏蔽中断 > 可屏蔽中断\
高速设备 > 低速设备\
输入设备 > 输出设备\
实时设备 > 普通设备
{: .prompt-info}

- 中断响应过程

\[图片]

CPU响应中断后，自动转而执行中断服务程序，这一过程（以下1 ~ 3）**由硬件实现**，称为`中断隐指令`（不是真正的指令），4 ~ 9由中断服务程序完成

1. 关中断

2. 保存断点：主要是将指令无法直接读取的**PC和PSW**内容保存在栈或特定寄存器内，过程中CPU不能响应更高级中断源的请求

3. 中断服务程序寻址：识别中断源（硬件向量法或软件查询法），将对应程序服务入口地址送入PC

4. 保存现场和屏蔽字：*现场信息*是用户可见的工作寄存器的内容

5. 开中断（仅多重中断）：以实现中断嵌套

6. 执行中断服务程序

7. 关中断（仅多重中断）

8. 恢复现场和屏蔽字

9. 开中断，中断返回：中断服务程序的最后一条指令通常是*中断返回指令*，使其返回到原程序断点处

> 异常和中断的差异：异常指令通常没有成功执行，在异常处理后重新执行，所以断点是当前指令的地址。中断的断点则是下一条指令的地址

> 中断向量：保存中断服务程序的**入口地址**，即中断向量地址是保存中断服务程序入口地址的地址；存放中断向量的存储区叫做中断向量表。
{: .prompt-info}

### DMA方式

DMA方式完全由硬件实现，名为直接存储器存取方式

适用于高速大批量数据的传输，硬件开销较大

在DMA方式中，中断的作用仅限于故障和传输结束时的处理

#### ：DMA控制器（DMA接口）

主要功能：

1. 接受外设发出的DMA总线请求，并向CPU发出总线请求，此过程统称`DMA请求`
2. CPU响应后，DMA接管总线控制权，进入DMA操作周期
3. 确定传输数据的主存起始地址和长度，并自动修改主存地址计数和传输长度计数
4. 规定数据在主存和外设间的传送方向，发出读写控制信号，执行数据传输
5. 向CPU报告DMA操作结束

#### ：DMA传输方式

DMA传输不占用CPU，但CPU和DMA可能同时占用主存，且IO访存优先级高于CPU（否则会导致数据丢失），因此有以下三种方式

- 停止CPU访存

当IO设备有DMA请求时，由DMA接口向CPU发送一个停止信号，传输结束后，再让CPU使用主存

- 周期挪用

是一种*单字传送*，IO设备传送完一个字的数据后释放总线

当IO设备有DMA请求时：
1. CPU不在访存：未冲突
2. CPU正在访存：冲突，待存取周期结束后，CPU让出总线使用权
3. IO和CPU同时请求：冲突，CPU让出总线使用权

- DMA与CPU交替访存

\[图片]

将CPU工作周期分为两块，一个给CPU访存，另一个给DMA访存，是自动分时控制，因此不需要申请、建立、归还总线使用权的步骤

#### ：DMA过程

分为预处理，传输，后处理三个阶段

\[图片]

- 预处理

由CPU完成一些必要的准备工作：
1. 初始化DMA控制器中的有关寄存器，设置传送方向，测试并启动设备
2. CPU继续执行原程序，直到IO设备准备好时，发出DMA请求

- 数据传送

传输阶段完全由DMA控制器控制，输入输出操作通过循环实现

> DMA以数据块为基本传输单位
{: .prompt-info}

- 后处理

DMA控制器向CPU发送**中断请求**，CPU执行中断服务程序，校验数据等

> DMA与中断方式的区别
1. 中断方式需要保护和恢复现场，而DMA不需要，仅在预处理和后处理阶段使用CPU
2. 响应中断请求只能在每条指令结束时，而响应DMA请求可以发生在任意一个机器周期结束时
3. DMA请求的优先级高于中断请求
4. 中断方式属于软件程序，DMA属于硬件方式
5. 中断需要占用CPU，而DMA传输过程不需要，因此传输速度高
6. 中断方式可以处理异常事件，而DMA仅限于数据传输
